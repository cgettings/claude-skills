### Validating the instrument

- **Citing a `file:line` as evidence means opening that file.** A grep hit proves the string exists, not that anything runs it - count occurrences rather than finding one, because an identifier appearing exactly once in its file is a declaration nothing consumes. Evidence: `~/.claude/lessons/file-line-citation-must-be-opened.md`.
- **A code comment is a claim, not evidence, and quoting it into a doc launders it into one.** Opening the file proves the comment exists - the check the `file:line` rule above asks for - and that is not enough when the thing cited is itself prose. Evidence: `~/.claude/lessons/code-comment-is-not-evidence.md`.
- **A null result from an instrument you have not validated is not a result.** Before reporting "nothing fired" - or building on it - prove the probe can fire at all with a positive control. Null results conceal their own failure: a probe that never reached the code under test and a code path that never ran are indistinguishable in the output.
    - The same applies to searches, in both directions: a pattern the shell mangled (`$'…'` survives as a bare argument but collapses to the empty pattern - matching every line - once nested inside `$( )` in a double-quoted string; the tell is a count equal to the file's line total, and the bare form is no better at detecting CRs that *are* present - count CR bytes with `tr -dc` piped to `wc -c`, not with `grep`), a tool whose domain silently excludes the target (`git grep` skips untracked files), or a well-formed pattern that simply cannot match a variant of the name it seeks (`lib-[a-z-]+\.html` cannot match `lib-d3.html`; `arquero\.[a-f0-9]*\.js` cannot match `arquero.min.<hash>.js`) yields a confident count that describes the search, not the code. The third has no error to notice, so prefer the shape that cannot have it: for "which members of set X are present", enumerate what is actually there and compare, rather than grepping once per expected member. Evidence: `~/.claude/lessons/search-failures-that-look-like-results.md`.
    - **One inflates rather than suppresses: the corpus records your own query.** Debug logs, shell history and session transcripts record the calls made against them, so a sweep finds its own probe. The tell is a count equal to the number of times you typed the term. Strip the tool-input echo lines before counting. Evidence: `~/.claude/lessons/corpus-records-your-own-query.md`.
    - **"Unchanged" is a null result too, and the comparison is the instrument.** A prefix, a length, or any field the encoding holds fixed reports "no change" against an artifact that did change. Compare whole values, and on two known-different inputs first. The mirror case reports change where there is none: `git cherry` compares patch-ids, so a commit reworked or squashed on its way in reads as unmerged though its content is present. The checkable form is tree identity, not a commit list: `git merge-tree --write-tree <base> <branch>` printing `<base>^{tree}` means the merge contributes zero bytes. Differing trees settle nothing the other way - the merge diff is positional, so content the base already carries at another line reads as an addition. Evidence: `~/.claude/lessons/unchanged-is-a-null-result.md`.
    - **A no-op proof is scoped to the unit you compare, not to the change you meant to test.** Strip-and-diff answers about the *file*, so a second change sharing it breaks the proof. Compare the commit's parent tree to its staged tree; a per-task commit split makes it exact for free. Evidence: `~/.claude/lessons/no-op-proof-scope.md`.
- **A check that only asks "did it succeed" passes on a degenerate result.** Assert the parsed value's type or shape, not that parsing returned: `json.loads` hands back a `str` and raises nothing for a document double-encoded as a JSON string literal. Same shape for a 200 response carrying an error page. Evidence: `~/.claude/lessons/degenerate-pass-on-did-it-succeed.md`.
- **A line-oriented search assumes one record per line; when the thing being counted can span lines, the count is wrong and looks right.** `grep '<img' | grep -v 'alt='` scores the opening line of every multi-line tag as a miss. Distinct from the three search failures above: the pattern is well-formed and does match. Count over parsed output - built HTML through a DOM query or axe - rather than over source lines. Evidence: `~/.claude/lessons/line-oriented-search-spans-records.md`.
- **A single-point reading cannot answer a question about change** - and the two axes fail the same way. *History:* to claim you introduced something, compute the property on the base commit too; a current-state grep answers "does this exist", never "is this new". *Time:* one post-event read cannot separate a fix that failed from a system that changed twice. Evidence: `~/.claude/lessons/single-point-reading-cannot-show-change.md`.
- **A derived structure is a function of the choices that produced it - vary each before reporting it.** Thresholds, reference points, population boundaries and exposure normalisation are free parameters, and a pattern visible under one setting can vanish under another. Name each free parameter and show the result at two settings, or report the structure as setting-dependent. Evidence: `~/.claude/lessons/derived-structure-free-parameters.md`.
- **A fixture field identical across every case it covers is dead, not passing.** Diff each field across a baseline's own cases before trusting it as a regression net: one constant everywhere is either constant by construction or reading a node that does not exist, and normalizing `null` to `""` is what disguises the second as the first. The sign narrows it for free: a constant `true`, non-empty string, or count of 1 or more cannot come from a probe that found nothing, so only a constant `0`/`false`/`null` needs an injection control. Evidence: `~/.claude/lessons/constant-fixture-field-is-dead.md`.
- **A detector's blind spot explains missed cases only if something falls through it.** Measure the set difference before reporting the gap as the cause. Evidence: `~/.claude/lessons/detector-blind-spot-must-contribute.md`.
- **A positive control rules out one explanation for a negative - count the explanations first.** Before reporting "it didn't load", "it didn't fire", "it isn't there", list every innocent reading that would look identical. Three explanations need three arms, not one control, and factorizing is the cheap way to get them: vary scope and the feature under test together, so each cell kills a different confound. One innocent reading is that the predicate encodes a *proxy* for the thing rather than the thing. Evidence: `~/.claude/lessons/count-the-explanations-for-a-negative.md`.
- **A positive control proves the probe can fire; it does not establish recall** - and when the control instance is also the one whose vocabulary you wrote the probe from, it is circular, confirming only that the pattern matches the text it was derived from. To assert a zero, derive the probe's terms from the definition of what you are looking for rather than from the hits you already have, or validate against a held-out instance. A cheap tell: count hits per file - if the file whose vocabulary you drew the pattern from holds an outsized share of them, the probe is circular. Evidence: `~/.claude/lessons/positive-control-does-not-establish-recall.md`.
- **A precondition check that reads the same field the measurement reads contaminates it.** Verify the precondition on a different instance than the one you perturb. Evidence: `~/.claude/lessons/precondition-check-contaminates-measurement.md`.
- **In a two-arm comparison, perturb the variable under test - never an input both arms share.** Perturbing the shared input moves both arms together, so the test passes whichever way the mechanism works. **Then run the shared-input injection as the OTHER arm.** Evidence: `~/.claude/lessons/perturb-the-variable-not-the-shared-input.md`.
- **A trigger that also moves something your classifier already explains gives a void arm, not a confounded one** - no information rather than noisy information. Name every field the trigger could move besides the one under test, and read those fields on the *first* boundary, not at the end. **Where an arm is cheap per turn, buy the check first.** Evidence: `~/.claude/lessons/trigger-that-moves-an-explained-field.md`.
- **One probe's positive control does not validate the others in the same harness.** A control that fires proves *that* probe can fire, not that the sweep beside it ran to completion. Any probe with a stop condition must emit why it stopped - input exhausted, or its own guard tripped - and its count checked against an expectation derived independently. Evidence: `~/.claude/lessons/one-probes-control-does-not-validate-others.md`.
- **A test run under conditions where the effect cannot occur is not evidence against it.** A positive control proves the *instrument* can fire; it does not prove the *conditions* could produce the thing being looked for. Before reporting a negative, state the conditions under which the effect would appear and confirm the test met them. **For an intermittent effect, agreement across N runs is weak evidence at any N** - reproduce it on demand or argue from mechanism, and say which you are doing. Evidence: `~/.claude/lessons/conditions-must-allow-the-effect.md`.
- **An eval or test prompt must not hand over the facts the thing under test is supposed to go find.** A prompt that narrates the session back to the agent scores identically for a model that read the transcript and one that didn't - the grounding step it was meant to exercise becomes invisible. Put required prior state in the expected output as a precondition, not in the user's mouth.
- **Before deleting content as "already covered elsewhere", verify the *claim* survives, not the keyword.** A grep proving the term appears does not prove the surviving copy asserts the same thing - and the copy you are deleting may be the newer one. Applies to memory hooks, duplicate doc sections, and consolidating audit findings. **When moving or splitting a document, check claim by claim, not section by section** - dropping content because its *category* is covered elsewhere is what makes a move lossy, and the loss is invisible in the diff.
